## 1. 확정한 방향

사진 자체에 선·그림·글씨를 덧그리는 그림일기다. 연결된 엽서, 리넨 바탕, 테라코타 강조색, 둥근 행동 버튼을 유지한다. 사진과 이야기가 중심이며 장식은 구분선과 연결부 정도로 제한한다.

`drawry :)`는 앱 로고다. `:)`는 제목과 같은 글자색을 사용하고 로고에만 둔다. 사진 아래, 서명, 빈 상태의 반복 장식으로 사용하지 않는다. 사진 속 손글씨는 사용자가 남긴 그림의 예시이며 앱이 자동으로 삽입하지 않는다.

Two Little Things / 두 장으로 남긴 하루 / 디자인 18은 설계 문서의 이름이다. 실제 앱의 고정 제목이나 일기 데이터로 넣지 않는다. 두 장은 대표 시안 구성이다. 사진 한 장으로도 기록할 수 있고, 여러 장은 순서대로 연결한다.

앱 아이콘은 **딸기 우유 스케치북**으로 확정한다. 흰 링 두 개, 핑크 표지, 풍경 사진, 로즈색 고리 모양 붓선을 유지한다. 화면의 리넨·테라코타 팔레트와 아이콘의 핑크 팔레트는 각각 지정된 역할에 사용한다.

## 2. 문구와 데이터의 역할

| 구분 | 항목 | 규칙 |
| --- | --- | --- |
| 고정 | drawry :) | 앱 이름. 사용자 일기 제목과 구분 |
| 고정 | 나의 기록 / 사진에 그리기 / 일기 쓰기 / 나의 일기 | 화면의 목적을 표시 |
| 고정 | 일기 제목 / 사진 이야기 / 선택 | 입력 전후 모두 남는 입력 라벨 |
| 직접 작성 | 일기 제목 | 기록 전체에 하나. 홈과 상세에 같은 값을 표시 |
| 직접 작성 | 사진 이야기 | 사진마다 선택 메모 하나. 별도의 사진 제목은 만들지 않음 |
| 직접 작성 | 사진 속 선·그림·글씨 | 해당 사진에 속한 편집 내용. 모드 전환으로 변경하지 않음 |
| 자동 | 기록 날짜 | 새 기록은 오늘로 시작. 작성 화면에서 날짜 변경 가능 |
| 자동 | 사진 1, 사진 2… / 사진 수 | 사용자가 정한 사진 순서와 실제 수에서 계산 |
| 선택 | 기분·태그 | 사용자가 선택하거나 입력. 비어 있으면 상세에서 숨김 |

입력 예시 `조금 느리게 보낸 오후`, `창가에서 마신 따뜻한 커피.`는 고정 문구가 아니다. `느린 오후 / 푸른 쉼` 같은 별도 사진 제목, `To. / From.` 서명, 내용 영역의 영문 장식 문구는 넣지 않는다.

### 빈 값과 긴 글

- 제목 앞뒤 공백을 제거한 값이 비면 표시 제목을 `{M}월 {d}일의 기록`으로 계산한다. 기준 날짜는 기록 날짜이며 생성일이나 현재 날짜가 아니다.
- 자동 표시 제목을 사용자 입력값으로 저장하지 않는다. 날짜를 바꾸면 빈 제목의 표시도 바뀐다.
- 사진 이야기가 비면 상세에서 라벨·자리표시자·빈 문단을 숨긴다. 홈에서도 빈 메모 공간을 강제하지 않는다.
- 입력 중 자리표시자는 사라지지만 `일기 제목 / 사진 이야기` 라벨은 남는다.
- 홈의 제목·메모는 각각 최대 두 줄 미리보기와 말줄임을 허용한다. 작성·상세는 전체 텍스트를 줄바꿈하고 세로 스크롤로 읽는다. 저장값을 잘라내지 않는다.
- 사진을 재정렬해도 이야기·그림은 사진의 고유 ID를 따라간다. 화면 번호만 새 순서로 계산한다.

## 3. 색상

라이트와 다크를 별도로 설계한다. 기본은 시스템 모드이며 설정에서 시스템·라이트·다크를 고를 수 있도록 구현한다. v1.1의 앱 화면 테마는 리넨 하나다. 딸기 우유 색감은 앱 아이콘에 사용한다. 시스템 배경화면 색상에 따라 앱 화면 팔레트를 바꾸지 않는다.

기본 본문과 활성 조작의 텍스트는 배경 대비 4.5:1 이상, 필수 입력 경계·아이콘·포커스는 3:1 이상을 내부 검수 기준으로 한다. 라이트의 보조 면 위 선택 글자는 강조색보다 짙은 `selectedText`를 사용한다. 얇은 장식 구분선은 입력 경계로 대체 사용하지 않는다. 오류는 색만 바꾸지 않고 설명과 재시도 행동을 제공한다.

다크에서는 바탕·엽서·조작부의 밝기를 나눈다. 사진, 직접 그린 선, 이미지 안의 글씨에는 반전·명도·테마 필터를 적용하지 않는다. 비활성 색은 비활성 상태에만 사용하며 활성 보조 글을 흐리게 만드는 용도로 쓰지 않는다.

## 4. 서체와 크기

Android 시스템 산세리프를 기본으로 한다. 별도 손글씨 폰트는 도입하지 않는다. 기기 기본 한글 글리프를 사용하고, 낙서 느낌은 사용자가 직접 그린 선으로 만든다. 로고의 `:)`는 시스템 세리프를 사용할 수 있으나 본문에는 혼용하지 않는다.

| 역할 | 크기 / 줄 높이 | 굵기 |
| --- | --- | --- |
| 앱 로고 | 28 / 36sp | 700 |
| 홈 화면 제목 | 28 / 36sp | 600 |
| 상단 화면 이름 | 20 / 28sp | 600 |
| 일기 제목 | 22 / 32sp | 600 |
| 목록의 일기 제목 | 18 / 26sp | 600 |
| 사진 이야기·본문 | 16 / 26sp | 400 |
| 입력 라벨·버튼 | 14 / 20sp | 500 |
| 날짜·보조 정보 | 12 / 18sp | 400 |

본문은 왼쪽 정렬, 기본 자간 0, 읽기 영역 최대 폭 640dp를 기준으로 한다. 한국어 어절을 우선 유지하되 긴 URL·붙여 쓴 글은 영역 안에서 줄바꿈한다. 임의 축소로 글을 끼워 넣지 않는다.

HTML의 320×700 전화기 그림은 여러 화면을 비교하기 위한 압축된 시안이다. 시안의 px 값을 dp/sp로 복사하지 않는다. 실제 앱은 위 크기와 동적 높이·스크롤을 적용하고 200% 글씨에서 재배치한다.

## 5. 간격·형태·아이콘

- 간격 체계: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48dp.
- 화면 좌우 여백 20dp, 카드 안쪽 16dp, 연속 항목 사이 12dp, 섹션 사이 24dp.
- 모서리: 사진 2dp, 엽서·입력 면 12dp, 도구함 24dp, 바텀 시트 28dp, 행동 버튼은 높이의 절반.
- 엽서는 얇은 1dp 경계로 구분한다. 라이트의 그림자는 약하게, 다크는 면의 밝기와 경계로 구분한다.
- 조작·탐색용 UI 아이콘은 24dp 선형, 둥근 끝, 약 1.75dp 선 굵기로 통일한다. 각 행동에 이름을 제공한다. 스케치북 앱 아이콘은 이 규칙의 대상이 아니며 11절을 따른다.
- 직접 만든 아이콘과 Android 표준 아이콘을 혼용할 때는 외곽 크기·선 굵기·무게를 맞춘다. 펜·지우개·이동·되돌리기를 색만으로 구분하지 않는다.
- 상태 표시줄, 시스템 탐색, 키보드 영역을 고려한 inset을 적용한다.

전환은 200ms, 눌림 피드백은 120ms를 기준으로 하며 반복되는 장식 애니메이션은 넣지 않는다. 시스템 모션 축소 설정에서는 전환을 줄이거나 생략한다. 작업 진행·저장 완료를 모션으로만 알리지 않는다.

## 7. 화면과 사진 수에 따른 배치

1. **홈:** 로고 → `나의 기록` → 기록 날짜 → 엽서 미리보기 → 같은 기록의 제목 → 기록하기. 여러 기록은 날짜 기준 목록으로 이어진다.
2. **그리기:** `사진에 그리기` → 사진 선택 → 한 장의 편집 면 → 도구함 → 적용. 그림 적용은 일기 저장과 구분한다.
3. **작성:** `일기 쓰기` → 날짜 변경 → 일기 제목 → 사진별 이야기 → 기분·태그 → 저장. 현재 사진·그림은 그대로 보며 글을 적는다.
4. **상세:** `나의 일기` → 기록 날짜 → 표시 제목 → 연결된 사진·이야기 → 기분·태그 → 수정·공유.

사진 한 장이면 한 장의 엽서로 표시하고 빈 두 번째 칸을 만들지 않는다. 두 장이면 현재 대표 시안처럼 연결한다. 세 장 이상은 홈에서 앞의 두 장과 `사진 N장`을 표시하고, 상세에서는 모든 사진을 순서대로 펼친다. 현재 저장 모델의 첨부 상한은 10개다. 대표 시안의 두 장을 제한값으로 사용하지 않는다.

사진은 원본 종횡비를 유지한다. 썸네일도 기본은 맞춤 표시이며 꽉 채우기 위해 자르지 않는다. 전체 보기와 그리기는 원본 좌표계에 맞춘 동일 변환을 사진과 그림에 함께 적용한다.

좁은 폭·큰 글씨에서 사진 옆 글 열이 좁아지면 사진 아래로 메모를 옮긴다. 두 장 홈 카드도 세로 배치로 전환할 수 있다. 사진 높이와 글 높이를 하나의 고정값으로 묶지 않는다.

compact는 하단 탐색을, 넓은 창은 탐색 레일·목록/상세 분할을 설계 목표로 한다. 구현에서는 현재 창 크기와 글씨 크기를 함께 고려한다. 키보드가 열리면 입력칸을 보이는 위치로 스크롤하고 저장 행동에 접근할 수 있게 한다.

## 8. 필수 상태와 문구

| 상황 | 표시 | 행동 / 보존 규칙 |
| --- | --- | --- |
| 기록 없음 | 아직 남긴 기록이 없어요 | 사진으로 시작하기 |
| 사진 없음 | 사진을 한 장 골라주세요 | 사진 선택. 입력한 글은 초안으로 보존 |
| 사진 메모 없음 | 작성 중에는 자리표시자 / 상세에서는 숨김 | 필수로 요구하지 않음 |
| 초안 저장 중 | 초안 저장 중… | 저장 완료를 미리 표시하지 않음 |
| 초안 저장 완료 | 초안이 저장되었어요 | 실제 저장 성공 후 표시 |
| 초안 저장 실패 | 초안을 저장하지 못했어요 | 글·그림 유지, 다시 시도 |
| 일기 저장 중 | 저장 중… | 중복 저장 방지, 완료 전 화면 이탈 처리 |
| 일기 저장 실패 | 저장하지 못했어요. 다시 시도해 주세요 | 입력값 유지, 다시 저장 |
| 사진 불러오기 실패 | 사진을 불러오지 못했어요 | 다시 시도 / 다른 사진 선택 |
| 시스템 사진 선택 취소 | 기존 작성 화면 유지 | 기존 사진·그림·글 변경 없음 |
| 초안 복구 | 작성하던 기록이 있어요 | 이어 쓰기 / 초안 버리기 |
| 변경 내용 버리기 | 작성한 내용을 버릴까요? | 계속 작성 / 버리기 |

그리기 화면에서 적용하면 해당 사진의 편집 결과를 작성 화면에 반영한다. 뒤로가기는 변경 여부에 따라 계속 그리기·적용·변경 버리기를 제공한다. 일기 전체의 저장 완료는 실제 저장 성공 뒤에 알린다.

## 9. 접근성과 검수

모든 조작은 최소 48×48dp 터치 영역을 갖고 서로 겹치지 않는다. 작은 아이콘의 시각 크기와 터치 영역은 구분한다. Compose의 기본 동작에만 의존하지 않고 실제 영역을 확인한다. [Android 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

텍스트는 sp, 여백은 dp로 다루며 200% 글씨에서도 내용·행동이 잘리지 않도록 검증한다. [Android 글씨 확대](https://developer.android.com/about/versions/14/features#non-linear-font-scaling)

TalkBack은 화면 이름 → 날짜 → 제목 → 사진과 해당 메모 → 행동 순서로 읽는다. 사진은 순서와 사용자가 쓴 메모를 활용하고, 손그림 내용을 앱이 추정하여 설명하지 않는다. 선택 도구·현재 사진·저장 상태는 의미 정보로 전달한다.

구현 완료 조건:

- 라이트·다크, 320/360/412dp 폭, 가로 화면, 키보드 표시, 200% 글씨에서 내용과 조작이 잘리지 않음.
- 사진 1·2·3·10장, 세로·가로·정사각 사진, 긴 제목·긴 메모·빈 제목·빈 메모에서 의미와 순서 유지.
- 제목·메모·날짜가 홈과 상세에서 일치하며 사진 재정렬 후에도 메모·그림이 올바른 사진을 따라감.
- 초안/저장 실패 후 입력값 보존, 원본 사진 보존, 모드 전환 전후 그림 좌표·색 유지.
- TalkBack의 라벨·선택 상태, 텍스트 대비, 겹치지 않는 터치 영역 확인.

이 항목들은 네이티브 구현의 합격 기준이다. 현재 HTML·PDF 검사 결과로 통과 처리하지 않는다.

## 10. Android 구현 인계

`DrawryTheme`에 색상·Typography·Shapes와 추가 간격 토큰을 묶고, 공통 버튼·입력·엽서를 먼저 만든다. Material 컴포넌트의 입력·접근성 동작을 활용하면서 위 시각 규칙을 적용한다. [Compose 사용자 정의 디자인 시스템](https://developer.android.com/develop/ui/compose/designsystems/custom)

현재 모델의 `Diary.headline`과 `entryDate`는 제목·기록 날짜에 대응한다. `Media.id`는 사진별 메모와 그림의 연결 기준이다. 현재 `Media`에는 사진별 이야기 필드가 없으므로 구현 전에 저장·복원 호환성을 설계해야 한다. 기존 `Diary.body`는 보존하고 사진 메모로 임의 분배하거나 지우지 않는다. 이번 디자인 확정으로 DRY2/DRBK2 포맷이나 사용자 DB를 변경하지 않는다.

캘린더·설정·잠금·백업/복원·휴지통·공유 화면의 상세 배치와 네이티브 구현은 다음 단계다. GitHub Actions는 사용자 실행 정책이 정해질 때까지 계속 중지한다.

## 11. 확정 앱 아이콘

**딸기 우유 스케치북 · 2026-10-21 사용자 승인.** 원본은 [app-icon.png](assets/app-icon.png), 1254×1254px RGB PNG이며 배경이 포함된 불투명 정사각 이미지다. 승인된 이미지의 픽셀을 변경하지 않고 최종 경로로 옮겼다. 생성 프롬프트·승인일·SHA-256은 [제작 기록](assets/app-icon.prompt.json)에 보관한다.

### 구성과 사용

- 왼쪽 흰 링 2개, 둥근 핑크 스케치북, 오른쪽 종이 가장자리, 흰 테두리의 풍경 사진, 고리 모양 붓선의 위치·비율을 유지한다.
- 라이트·다크 모두 같은 원본을 사용한다. 아이콘에 반전·자동 틴트·밝기·색상 필터를 적용하지 않는다.
- 정사각 비율과 포함된 여백을 유지해 비례 축소한다. 링·표지·붓선을 임의로 자르거나 늘리지 않는다.
- 하트·표정·글자·배지·추가 장식을 원본 안에 합성하지 않는다. 상단 이름은 기존 `drawry :)` 규칙을 따른다.
- 작은 크기에서는 스케치북·링·사진·붓선의 형태를 우선 확인한다. HTML의 72/48/32 CSS px 표시는 검토 예시이며 Android 런처 검증 결과가 아니다.

### 네이티브 자산 인계

확정 범위는 시각 원본과 사용 기준이다. 적응형 런처용 전경·배경, 시스템 테마용 단색 자산, 필요한 크기별 출력은 구현 단계에서 별도로 준비한다. 원본을 단순 흑백 필터로 바꾼 파일을 승인된 단색 아이콘으로 취급하지 않는다. 마스크별 링·표지·붓선 잘림과 실제 기기 표시를 확인한 뒤 적용한다. 현재 Android의 임시 D 런처 리소스는 교체 전이다.
